Five issues only an agent on live data can resolve

Disk cleanup and device restarts work fine on delayed data: the problem is still there an hour later. The next tier of L1 tickets is about what is going wrong right now.

The employee says
Spark sees, live
+SMART sees, from the datalake
"My virtual desktop is lagging right now."VDI session, during work

This session's current latency, logon and responsiveness, the load on its host and the network path, through VDI Experience.

Fix: resets the stuck client or session; if the host itself is saturated, hands L2 a ready diagnosis instead of a vague ticket.

The session degraded after the last ingestion. The agent sees a normal session and can only suggest reconnecting.

"My laptop became unusable five minutes ago."Sudden performance drop

The process that started minutes ago and saturates CPU, memory or disk: a runaway browser tab, an indexing job, a stuck update.

Fix: stops or restarts it with the employee's consent, shows the device back to normal.

A healthy device from an hour ago. Default answer: restart, losing unsaved work, without knowing the cause.

"I just arrived at the office and VPN won't connect."Network change, travel, hotel Wi-Fi

The network the device is on now, DNS resolution, VPN client state and certificate validity.

Fix: resets the adapter or DNS cache, restarts the VPN client, confirms the connection.

The device still connected from home an hour ago. The new network doesn't exist in its data.

"My business app just crashed and won't reopen."Application failure after an update

The crash event seconds ago, the faulting module, and the update that landed this morning, through Application Experience.

Fix: clears the app cache or runs a repair, then relaunches and checks for a new crash.

No crash recorded yet. The agent may answer that the app is running normally.

"Outlook keeps asking for my password since I changed it."Sign-in loop after password change

The repeated authentication prompts now, stale cached credentials and the account state.

Fix: clears cached credentials, restarts Outlook, confirms mailbox sync resumed.

The password change happened after the last sync. The loop is invisible, so a ticket to the service desk.

The hidden cost of latency: no proof the fix worked

Even on simple use cases, an agent on delayed data can't confirm its own fix inside the conversation. Spark checks the outcome on live data before closing, so "resolved" means resolved, not "ticket avoided until the employee calls back."

Five use cases Flow unlocks for Spark

A remote action is a single script on a device. Flow lets Spark chain actions, call your other systems, branch on conditions, retry and pick up again after a reboot, so whole requests are resolved end to end instead of handed to a person halfway. +SMART remediates through remote actions today, so the limits described in the next section apply to your agent today.

Action on the device API call, credentials kept in Nexthink Condition, branch or repeat Reboot, then Flow resumes

1. Software request with licence check and approval

"I need Visio." Today a service request that waits days for approval and licence allocation.

  1. Check licence pool in the SaaS admin API
  2. No seat free: reclaim an unused licence
  3. Request manager approval in the ITSM tool
  4. Install the software
  5. Verify it launches
  6. Close the request automatically

2. Account locked or lost MFA device

"I'm locked out and got a new phone." One of the highest-volume L1 calls, impossible with a device-only script.

  1. Check account status in Entra ID via Graph API
  2. Locked: unlock the account
  3. MFA device lost: verify identity, issue a temporary access pass
  4. Log the action in the ITSM tool
  5. Confirm sign-in works

3. Deep performance fix that needs a reboot

"My PC has been slow for days." A remote action stops at the reboot; Flow carries on.

  1. Clean temp files and caches
  2. Repair system files
  3. Reboot at a time the employee picks
  4. Resume: measure boot time and responsiveness
  5. Still degraded: open an L2 ticket with the full diagnosis

4. Device non-compliant, email access blocked

"I can't access my email on this laptop." Conditional access blocks work until a patch installs.

  1. Read compliance state in Intune via Graph API
  2. Trigger a device sync
  3. Repeat until the update installs, up to a limit
  4. Reboot, then resume
  5. Confirm compliant, access restored

5. Failing battery replaced before it strands the employee

"My laptop dies after an hour." Diagnosis, warranty and ordering usually take three teams.

  1. Read battery health and wear
  2. Check warranty with the hardware vendor's API
  3. Under warranty: order replacement; otherwise route to procurement
  4. Create the hardware request with serial and diagnosis
  5. Tell the employee when and where to swap it
